# First Week Timeline
## Day-by-Day Onboarding Schedule

This timeline ensures a structured, predictable onboarding experience for your new MSP clients. Share this with the client on day 0 so they know what to expect each day.

---

## Overview

The first week is critical. It sets expectations, builds trust, and establishes your processes. This timeline keeps both your team and the client aligned.

**Key principle:** Every day has a specific objective. No wasted time, no surprises.

---

## MONDAY (Day 1)

### Morning: Kickoff Call
**Duration:** 60 minutes  
**Participants:** Client, Account Manager, Technical Lead  
**Objective:** Establish rapport, confirm scope, begin technical discovery

#### Agenda
- [ ] Welcome & thank you for signing
- [ ] Introduce account team & support structure
- [ ] Review service level agreement (SLA) expectations
- [ ] Walk through checklist — collect outstanding items
- [ ] Schedule discovery assessment
- [ ] Confirm primary contact for urgent issues
- [ ] Q&A

**Deliverables:**
- Client has: Account manager direct contact info
- We have: Updated contact list, outstanding checklist items identified

### Afternoon: Internal Team Meeting
**Duration:** 30 minutes  
**Participants:** Account Manager, Technical Lead, Security Officer  
**Objective:** Assign roles, prioritize discovery items

#### Agenda
- [ ] Assign primary technician
- [ ] Assign backup/secondary support
- [ ] Identify technical discovery priorities
- [ ] Review compliance requirements
- [ ] Create implementation timeline
- [ ] Set internal follow-up tasks

---

## TUESDAY (Day 2)

### Morning: Client Portal Setup
**Deliverables to client:**
- [ ] Portal access credentials sent (secure method)
- [ ] Portal user guide attached
- [ ] Knowledge base links provided
- [ ] Support ticket submission instructions

**Client action:** Reset password, log into portal, test access

### Afternoon: Initial Assessment Begins
**Deliverables:**
- [ ] Network diagram received or scheduled
- [ ] Hardware inventory preliminary review
- [ ] Current backup/disaster recovery assessed
- [ ] Critical system dependencies identified

**Internal:** Begin documentation review, start building network topology inside RMM/monitoring tool

---

## WEDNESDAY (Day 3)

### Full Day: Technical Discovery Session
**Duration:** 2-3 hours  
**Location:** On-site (preferred) or via remote screen share

**Participants:** Technical Lead + 1 specialist (based on needs: networking, security, infrastructure)

#### Discovery Checklist
- [ ] Physical server/hardware walkthrough
- [ ] Network closet inspection
- [ ] Backup system review & testing
- [ ] Firewall/security appliance review
- [ ] Documentation gaps identified
- [ ] Performance baseline assessment
- [ ] Identify quick-wins (low-hanging fruit improvements)

**Deliverables:**
- Initial discovery report (internal use)
- Identified risks or concerns
- Photos/documentation captured
- Follow-up items documented

---

## THURSDAY (Day 4)

### Morning: Monitoring & RMM Deployment
**Technician tasks:**
- [ ] Install monitoring agent on servers
- [ ] Install RMM (remote management) agent on workstations (sample or all, per agreement)
- [ ] Configure antivirus management console access
- [ ] Set up backup verification
- [ ] Begin initial data collection

**Client communication:**
- Notify IT team of any system restarts needed
- Explain what monitoring data will show
- Confirm support ticket process

### Afternoon: Security Assessment Begins
**Deliverables:**
- [ ] Firewall rule audit started
- [ ] User account review (active directory, local admin audit)
- [ ] Password policy assessment
- [ ] Multi-factor authentication (MFA) readiness review
- [ ] Compliance gap analysis (if required)

---

## FRIDAY (Day 5)

### Morning: Executive Summary Presentation (Internal Prep)
**Duration:** 30 minutes  
**Participants:** Account Manager + Technical Lead  
**Objective:** Prepare client-facing findings & recommendations

#### Create Internal Report
- [ ] Summarize discoveries this week
- [ ] Identify 5-10 key findings/risks
- [ ] Categorize as: Critical, High, Medium, Low risk
- [ ] Draft preliminary recommendations
- [ ] Estimate effort/cost for improvements

### Afternoon: End-of-Week Check-in Call
**Duration:** 30-45 minutes  
**Participants:** Client point of contact + Account Manager  
**Objective:** Reassure client, preview next steps, collect feedback

#### Agenda
- [ ] "How are we doing?" — address any concerns
- [ ] Recap what we've learned so far
- [ ] Preview next week's focus areas
- [ ] Confirm any quick-wins we can start
- [ ] Schedule formal assessment presentation
- [ ] Confirm all checklist items received

**Deliverables:**
- [ ] Client feels informed & confident
- [ ] Next week's schedule confirmed
- [ ] Any urgent issues escalated

---

## Week 1 Success Metrics

Client should have:
- ✅ Portal access working
- ✅ Primary contact established & responsive
- ✅ Monitoring/RMM agent installed
- ✅ Initial assessment completed
- ✅ Clear understanding of next steps

Your team should have:
- ✅ Complete network documentation
- ✅ Hardware/software inventory
- ✅ Identified risks & compliance gaps
- ✅ Initial recommendations drafted
- ✅ Implementation timeline created

---

## Potential Issues & Contingencies

| Issue | If This Happens | Then Do This |
|-------|-----------------|--------------|
| **Client unavailable for kickoff** | Reschedule to Day 2 | Send async checklist reminder email |
| **Portal access fails** | Check credentials, test from scratch | Escalate to IT quickly, offer workaround ticket system |
| **Hardware access restricted** | Can't assess systems on Day 3 | Get credentials/access immediately or reschedule |
| **Checklist items incomplete** | Missing network docs or credentials | Call client, explain why needed, set 48-hour deadline |
| **Critical security issue found** | Firewall misconfiguration, open ports, etc. | Flag immediately to Account Manager & client leadership |
| **Staff turnover delays process** | Key employee on vacation | Identify backup contact immediately, document handoff |

>

>
> **Monday:** Account manager calls — we'll review your service level agreement and confirm what we're covering
>
> **Tuesday:** You'll get portal access and we begin reviewing your infrastructure
>
> **Wednesday:** Our engineer visits/calls to do a detailed technical discovery
>
> **Thursday:** We install monitoring and begin security assessment
>

> - Designate a day-to-day contact for our team
> - Be available for the Wednesday discovery session
>
